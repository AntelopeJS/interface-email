The interface has four attachment types, one per source of file data. All four share the `BaseAttachment` fields. You pass them in the `attachments` field of `EmailParams` or `TemplateEmailParams`.

## Choose the source of the bytes

| You already have                       | Use                | Supply                                     |
| -------------------------------------- | ------------------ | ------------------------------------------ |
| Bytes in memory                        | `BufferAttachment` | `content: Buffer`                          |
| Base64-encoded bytes                   | `Base64Attachment` | `content: string` and `encoding: "base64"` |
| A file available to the implementation | `PathAttachment`   | `path`                                     |
| A file reachable by the implementation | `UrlAttachment`    | `url`                                      |

A path is a path on the server that runs the implementation, not on the recipient's computer. Use trusted or validated paths and URLs. Do not let untrusted input pick arbitrary local files or internal network addresses. Check the provider's size limits before you send.

## Attachment types

### `BufferAttachment`

Use `BufferAttachment` when the file data is in memory as a Node.js `Buffer`, for example a file you generate or read from a stream.

```ts
import { Send, type BufferAttachment } from "@antelopejs/interface-email";

const reportBuffer = Buffer.from(
  "Quarterly report\nRevenue: 12500 EUR\n",
  "utf8",
);

const attachment: BufferAttachment = {
  filename: "report.txt",
  contentType: "text/plain",
  content: reportBuffer,
};

await Send({
  to: "user@example.com",
  subject: "Your Report",
  text: "Please find the attached report.",
  attachments: [attachment],
});
```

### `Base64Attachment`

Use `Base64Attachment` when the file data is a base64 string. The `encoding` field is `"base64"`, and it tells this type apart from a `BufferAttachment`.

```ts
import { Send, Base64Attachment } from "@antelopejs/interface-email";

const attachment: Base64Attachment = {
  filename: "notes.txt",
  contentType: "text/plain",
  content: "SGVsbG8h", // Base64 for "Hello!"
  encoding: "base64",
};

await Send({
  to: "user@example.com",
  subject: "Meeting Notes",
  text: "Notes attached.",
  attachments: [attachment],
});
```

### `PathAttachment`

Use `PathAttachment` to attach a file from the local filesystem by its path. Reading the file is provider behaviour. `@antelopejs/nodemailer` passes the path to Nodemailer, which reads the file when it sends. `@antelopejs/brevo` does not support `PathAttachment`. It logs an error and sends the message without that file.

```ts
import { Send, PathAttachment } from "@antelopejs/interface-email";

const attachment: PathAttachment = {
  filename: "data-export.csv",
  contentType: "text/csv",
  path: "/tmp/exports/data-export-2026.csv",
};

await Send({
  to: "analyst@example.com",
  subject: "Data Export",
  text: "The requested export is attached.",
  attachments: [attachment],
});
```

### `UrlAttachment`

Use `UrlAttachment` to attach a file from a remote URL. Fetching the file is provider behaviour. `@antelopejs/nodemailer` passes the URL to Nodemailer, which fetches it when it sends. `@antelopejs/brevo` passes the URL to the Brevo API.

```ts
import { Send, UrlAttachment } from "@antelopejs/interface-email";

const attachment: UrlAttachment = {
  filename: "handbook.pdf",
  contentType: "application/pdf",
  url: "https://cdn.example.com/docs/handbook-v3.pdf",
};

await Send({
  to: "new-hire@example.com",
  subject: "Employee Handbook",
  text: "Please review the attached handbook.",
  attachments: [attachment],
});
```

## Inline images

An inline attachment puts an image in the HTML body through a Content-ID reference. Set `inline` to `true`, give the attachment a `cid` value, then reference it in your HTML with the `cid:` scheme. How the provider applies `inline` and `cid` is provider behaviour. `@antelopejs/nodemailer` passes `cid` to Nodemailer and does not read `inline`. `@antelopejs/brevo` sends neither `cid` nor `inline` to the Brevo API, so the image arrives as a plain attachment ([AntelopeJS/brevo#44](https://github.com/AntelopeJS/brevo/issues/44)).

The following example reads a PNG at `./assets/logo.png`, relative to the working directory of the server. Supply that file before you run it.

```ts
import { readFile } from "node:fs/promises";
import { Send } from "@antelopejs/interface-email";

const logoBuffer = await readFile("./assets/logo.png");

await Send({
  to: "user@example.com",
  subject: "Welcome",
  html: `
    <div>
      <img src="cid:company-logo" alt="Company Logo" />
      <h1>Welcome to our platform!</h1>
    </div>
  `,
  attachments: [
    {
      filename: "logo.png",
      contentType: "image/png",
      content: logoBuffer,
      cid: "company-logo",
      inline: true,
    },
  ],
});
```

`(await GetCapabilities()).features.inlineAttachments` tells you what the implementing module reports, not what it does. `@antelopejs/brevo` reports `true` and still does not inline the image, so test inline images with your provider before you rely on them.

## Multiple attachments

The `attachments` field takes an array, so one email can mix attachment types:

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "client@example.com",
  subject: "Project Deliverables",
  text: "All deliverables are attached.",
  attachments: [
    {
      filename: "proposal.pdf",
      contentType: "application/pdf",
      path: "/documents/proposal.pdf",
    },
    {
      filename: "mockup.png",
      contentType: "image/png",
      url: "https://cdn.example.com/mockups/v2.png",
    },
    {
      filename: "notes.txt",
      contentType: "text/plain",
      content: Buffer.from("Meeting notes for the project kickoff."),
    },
  ],
});
```

## The `BaseAttachment` interface

Every attachment requires a filename. These shared fields apply to all four types:

| Field         | Type      | Required | Description                                                       |
| ------------- | --------- | -------- | ----------------------------------------------------------------- |
| `filename`    | `string`  | Yes      | The filename shown to the recipient                               |
| `contentType` | `string`  | No       | MIME type, such as `"application/pdf"`                            |
| `cid`         | `string`  | No       | Content-ID for inline images (reference in HTML as `cid:yourCid`) |
| `inline`      | `boolean` | No       | If `true`, embed in the HTML body instead of attaching as a file  |

## The `Attachment` union type

The `Attachment` type is the union of the four attachment interfaces:

```ts
import type {
  Base64Attachment,
  BufferAttachment,
  PathAttachment,
  UrlAttachment,
} from "@antelopejs/interface-email";

type Attachment =
  BufferAttachment | Base64Attachment | PathAttachment | UrlAttachment;
```

When you build attachments at runtime, an `in` check on `encoding`, `path`, or `url` narrows an `Attachment` to one member. An attachment with `content` and no `encoding` is a `BufferAttachment`.
