The interface has three sending functions: `Send` for single emails, `SendTemplate` for template-based emails, and `SendBatch` for multiple emails in one operation.

For a first message, start with [`EmailParams`](#the-emailparams-object), then read the [response](#email-response). Add [templates](#template-emails), [batches](#batch-sending), or optional fields only when the workflow needs them. Optional features depend on [provider capabilities](./1.introduction.md#provider-capabilities).

## The `EmailParams` object

The `Send` function takes an `EmailParams` object. Only `to` and `subject` are required. Every other field is optional.

```ts
import { Send } from "@antelopejs/interface-email";

const response = await Send({
  to: "user@example.com",
  subject: "Welcome aboard",
  html: "<h1>Welcome!</h1><p>Thanks for joining.</p>",
  text: "Welcome! Thanks for joining.",
});

if (!response.success) {
  throw new Error(
    response.error?.message ?? "The provider did not accept the email",
  );
}
console.log(response.status); // Acceptance is not proof of inbox delivery.
```

This example uses the configured default sender. Handle rejected promises at your
application boundary as well as unsuccessful responses. [Email response](#email-response)
lists the optional fields and the precautions for retries.

### Required fields

| Field     | Type                             | Description            |
| --------- | -------------------------------- | ---------------------- |
| `to`      | `EmailAddress \| EmailAddress[]` | One or more recipients |
| `subject` | `string`                         | The email subject line |

### Content fields

Provide `text`, `html`, or both, even though the TypeScript type makes both optional. With both, readers get a plain-text alternative to the HTML.

| Field  | Type     | Description     |
| ------ | -------- | --------------- |
| `text` | `string` | Plain text body |
| `html` | `string` | HTML body       |

### Address fields

| Field     | Type                             | Description                                      |
| --------- | -------------------------------- | ------------------------------------------------ |
| `from`    | `EmailAddress`                   | Sender address (the provider default if omitted) |
| `replyTo` | `EmailAddress \| EmailAddress[]` | One or more reply-to addresses                   |
| `cc`      | `EmailAddress \| EmailAddress[]` | CC recipients                                    |
| `bcc`     | `EmailAddress \| EmailAddress[]` | BCC recipients                                   |

### Threading fields

These fields place an email in an existing thread:

| Field        | Type                 | Description                              |
| ------------ | -------------------- | ---------------------------------------- |
| `messageId`  | `string`             | Custom Message-ID header                 |
| `inReplyTo`  | `string`             | Message-ID of the email being replied to |
| `references` | `string \| string[]` | Message-IDs of the thread                |

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "user@example.com",
  subject: "Re: Project update",
  text: "Thanks for the update!",
  inReplyTo: "<original-message-id@example.com>",
  references: ["<original-message-id@example.com>"],
});
```

## Email priority

The `priority` field requests a priority from providers that support it. It does not guarantee faster delivery. Check `features.priority` on the awaited provider capabilities before you rely on this option. The interface sets no default priority.

| Value      | Description                                 |
| ---------- | ------------------------------------------- |
| `"high"`   | Request high priority for an urgent message |
| `"normal"` | Standard delivery priority                  |
| `"low"`    | Non-urgent emails such as newsletters       |

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "admin@example.com",
  subject: "Server Alert",
  text: "CPU usage exceeded 95%.",
  priority: "high",
});
```

## Tracking options

The `tracking` field sets open and click tracking through the `TrackingOptions` interface.

| Field            | Type      | Description                              |
| ---------------- | --------- | ---------------------------------------- |
| `opens`          | `boolean` | Track when the recipient opens the email |
| `clicks`         | `boolean` | Track when the recipient clicks links    |
| `trackingDomain` | `string`  | Custom domain for tracking URLs          |
| `disabled`       | `boolean` | Disable all tracking                     |

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "user@example.com",
  subject: "Monthly Report",
  html: "<p>Your report is ready. <a href='https://app.example.com/reports'>View it here</a>.</p>",
  tracking: {
    opens: true,
    clicks: true,
    trackingDomain: "track.example.com",
  },
});
```

## Schedule options

The `schedule` field delays delivery to a given time through the `ScheduleOptions` interface.

| Field      | Type             | Description                                             |
| ---------- | ---------------- | ------------------------------------------------------- |
| `sendAt`   | `Date \| string` | When to send the email (ISO 8601 string or Date object) |
| `timezone` | `string`         | IANA timezone identifier, such as `"Europe/Paris"`      |

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "team@example.com",
  subject: "Monday Standup Reminder",
  text: "Standup in 15 minutes.",
  schedule: {
    sendAt: new Date("2027-04-05T06:45:00Z"),
    timezone: "Europe/Paris",
  },
});
```

Before you schedule a message, check `(await GetCapabilities()).features.scheduling` to confirm that the provider supports it.

Await `GetCapabilities()` before you read its flags. Give an explicit UTC offset when you construct a `Date`. The example is 08:45 in Paris on that date. A `timezone` field does not change how JavaScript parses a date string that has no timezone.

## Tags and metadata

Tags and metadata label emails for analytics and tracking.

| Field      | Type                     | Description                                       |
| ---------- | ------------------------ | ------------------------------------------------- |
| `tags`     | `string[]`               | Labels for categorization and analytics           |
| `metadata` | `Record<string, string>` | Custom key-value pairs returned in webhook events |

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "user@example.com",
  subject: "Order Confirmation",
  html: "<p>Your order #12345 has been confirmed.</p>",
  tags: ["transactional", "order-confirmation"],
  metadata: {
    orderId: "12345",
    userId: "usr_abc",
  },
});
```

## Provider options

The `providerOptions` field passes provider-specific settings that the interface does not define. Use it sparingly, because it makes the code less portable. The value is a `JsonObject`. Every nested value is a string, a number, a boolean, `null`, an array of such values, or an object of them. A key whose value is `undefined` is accepted, so you can pass an optional field as is. `JSON.stringify` drops such a key. The implementing module decides which keys it reads. Neither `@antelopejs/nodemailer` nor `@antelopejs/brevo` reads `providerOptions`.

```ts
import { Send } from "@antelopejs/interface-email";

await Send({
  to: "user@example.com",
  subject: "Test",
  text: "Hello",
  providerOptions: {
    sendgridIpPoolName: "transactional",
  },
});
```

## Template emails

The `SendTemplate` function renders an email from a template before it sends. A template is either hosted by the provider or defined inline.

### Provider-hosted templates

A `ProviderTemplate` names a template stored in the provider's system by its ID. The ID format is provider behaviour. `@antelopejs/brevo` expects a numeric ID, and `@antelopejs/nodemailer` does not support provider-hosted templates.

```ts
import { SendTemplate } from "@antelopejs/interface-email";

const response = await SendTemplate({
  to: "user@example.com",
  template: { id: "welcome-v2", version: "3" },
  variables: {
    name: "Alice",
    activationUrl: "https://app.example.com/activate?token=xyz",
  },
});
```

### Inline templates

An `InlineTemplate` carries the template content, its `type`, and an optional `engine` hint:

```ts
import { SendTemplate } from "@antelopejs/interface-email";

const response = await SendTemplate({
  to: "user@example.com",
  template: {
    content: "<h1>Hello {{name}}</h1><p>Welcome to our platform.</p>",
    type: "html",
    engine: "handlebars",
  },
  variables: { name: "Alice" },
});
```

Template variables are a `JsonObject` too, so `variables` and each `recipientVariables` entry cannot carry a `Date`, a `Buffer`, or a function. Convert such a value before you send, for example with `toISOString()`. TypeScript rejects an object declared with an `interface`, because it has no index signature. Declare it with a `type` alias, or spread it into a literal (`{ ...user }`).

### Per-recipient variables

To give each recipient their own values, key `recipientVariables` by email address:

```ts
import { SendTemplate } from "@antelopejs/interface-email";

await SendTemplate({
  to: ["alice@example.com", "bob@example.com"],
  template: { id: "weekly-digest" },
  variables: { week: "March 23-29" },
  recipientVariables: {
    "alice@example.com": { name: "Alice", unreadCount: "5" },
    "bob@example.com": { name: "Bob", unreadCount: "12" },
  },
});
```

## Batch sending

The `SendBatch` function sends multiple emails in a single operation. Each message in the batch is an `EmailParams` object with an optional `batchId` to match it with its response.

```ts
import { SendBatch } from "@antelopejs/interface-email";

const result = await SendBatch({
  messages: [
    {
      to: "alice@example.com",
      subject: "Your invoice",
      html: "<p>Your invoice #001 is ready in your account.</p>",
      batchId: "invoice-001",
    },
    {
      to: "bob@example.com",
      subject: "Your invoice",
      html: "<p>Your invoice #002 is ready in your account.</p>",
      batchId: "invoice-002",
    },
  ],
  defaults: {
    from: { email: "billing@myapp.com", name: "Billing" },
    tags: ["invoice"],
  },
  continueOnError: true,
});
```

### Batch defaults

The `defaults` field holds values shared by all messages. The interface leaves the merge to the implementing module. `@antelopejs/nodemailer` spreads `defaults` under each message, so a field set on the message wins. `@antelopejs/brevo` merges recipients, subject, body, and attachments the same way, but takes the sender, `tags`, and `schedule` of the batch from `defaults` only.

### Error handling in batches

When `continueOnError` is `true` (the default), the batch keeps sending after a message fails. The response has one result per message:

```ts fragment
console.log(result.total); // Total messages in batch
console.log(result.successful); // Number sent successfully
console.log(result.failed); // Number that failed

for (const res of result.responses) {
  if (!res.success) {
    console.error(
      `Message ${res.batchId} to ${res.recipient} failed:`,
      res.error,
    );
  }
}
```

## Email response

The `Send` and `SendTemplate` functions return an `EmailResponse` object:

| Field       | Type          | Description                                   |
| ----------- | ------------- | --------------------------------------------- |
| `success`   | `boolean`     | Whether the email was accepted                |
| `status`    | `EmailStatus` | Current delivery status                       |
| `messageId` | `string`      | Provider-assigned ID for tracking             |
| `error`     | `EmailError`  | Error details if the send failed              |
| `timestamp` | `Date`        | When the email was accepted                   |
| `provider`  | `string`      | Name of the provider that handled the request |

The `EmailStatus` type includes these values: `"queued"`, `"sent"`, `"delivered"`, `"failed"`, `"rejected"`, `"scheduled"`, and `"unknown"`.

Only `success` and `status` are required on `EmailResponse`. Message IDs, errors, timestamps, and provider names can be absent. In a batch, each result also has an `index` into the original messages and a `recipient`. Its `batchId` is optional. The batch-level `success` is true only when every message succeeds.

### Error handling

When `success` is `false`, read the optional `error` field for an `EmailError` object:

```ts
import { Send } from "@antelopejs/interface-email";

const response = await Send({
  to: "user@example.com",
  subject: "Hello",
  text: "World",
});

if (!response.success && response.error) {
  console.error(`Error [${response.error.code}]: ${response.error.message}`);

  if (response.error.retryable) {
    // A retry may succeed; apply your retry and duplicate-send policy.
  }
}
```

`retryable` is a hint. It does not make a retry safe to repeat, because a retry can send another message and the interface defines no deduplication key. `EmailError` requires `code` and `message`, and has the optional `field` and `retryable`. Also handle rejected promises from the configured implementation.
